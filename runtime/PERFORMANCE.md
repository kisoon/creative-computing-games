# ml5 영상 처리 성능 보완 — 2026-11-23

학생 작품의 모델·가중치·정밀도·반전·좌표·인식 주기와 화면·효과·판정·게임 규칙은 유지합니다. 변경 대상은 공통 ml5 실행 어댑터와 말랑이의 영상 복사 어댑터입니다.

## 변경

이전에는 모델마다 모니터 주기에 맞춰 같은 영상을 canvas에 반복 복사했습니다. 이제 같은 video의 원본 크기 canvas와 한 개의 영상 갱신 루프를 공유합니다. 새 카메라 프레임만 복사하고 이미 복사한 프레임을 다시 요구하면 재사용합니다. 단발 detect도 같은 현재 프레임을 사용하지만 모델 추론 호출과 결과 콜백은 그대로 수행합니다.

requestVideoFrameCallback 지원 환경에서는 카메라 프레임에 맞춰 갱신합니다. 미지원 환경은 requestAnimationFrame과 프레임 번호/영상 시간을 사용합니다. 시작 전 프레임 준비 대기, 마지막 모델 정지 시 갱신 취소, 로딩 중 취소, 비활성 카메라 및 페이지 종료 정리도 검사합니다. [브라우저 API 설명](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback).

말랑이의 별도 canvas/복사 루프를 공통 어댑터로 통합했습니다. 기존 WebGL 설정, 손 모델 옵션, 최신 결과 처리와 만료 시간은 유지합니다.

## 동일 조건 비교

macOS Chrome / Apple M2, 400×350·15fps 가상 카메라에서 각 작품을 7초 준비한 뒤 8초 측정했습니다.

| 작품 | 이전 영상 복사 | 이후 영상 복사 | 감소 |
|---|---:|---:|---:|
| 손바닥 과일 받기 | 480 | 120 | 75% |
| Elsa Filter (손·얼굴·몸 3개) | 1,440 | 120 | 91.7% |
| 말랑이 | 480 | 120 | 75% |
| Ink Mirror | 480 | 120 | 75% |

측정한 화면 프레임 간격의 95백분위수는 전후 약 16.7~16.8ms였습니다. 기존 환경이 이미 약 60fps였으므로 전체 FPS가 그 비율로 빨라졌다는 의미는 아닙니다. 줄어든 수치는 중복 영상 복사 작업량입니다. 해상도·인식 정확도를 낮추거나 인식 빈도를 제한하지 않았으며, 기기별 전체 체감 속도는 별도 차이가 있습니다. [원시 측정값](performance-results.json).

## 검증

`node runtime/tests/ml5-support.cjs`로 세 모델의 프레임 공유, 새 프레임 갱신, 해상도 보존 및 변경, 원래 결과 객체 전달, 모델 독립 정지, 전체 종료, 구형 브라우저 대체 동작을 검사합니다. 실제 Chrome에서도 18개 작품 모두 추론 콜백을 반환했고 페이지 오류와 요청 실패가 없었습니다. 손·얼굴·몸 입력을 분리해 해당 좌표 반환을 확인했습니다. [브라우저 결과](performance-browser-results.json). 비 ml5 작품과 학생용 README는 수정하지 않습니다.
